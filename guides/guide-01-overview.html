Skills vs MCP vs Plugins

Four tabs. Each one walks through one concept with a working simulation. Start with skills, work through to the compare table.

A Skill is a folder with a markdown file.

A Skill is literally a folder named after the skill, containing one required file called SKILL.md. The folder can also contain helper scripts, reference docs, templates, whatever the skill needs.

On Windows 11, personal skills live in C:\Users\you\.claude\skills\. Project skills go in .claude\skills\ inside your repo so the whole team gets them.

Watch conditional loading actually happen

At startup, Claude does NOT load the full body of every skill. It only reads the small description from each SKILL.md frontmatter. That is 30 to 50 tokens per skill. So you can have 100 skills installed and pay almost nothing. When you send a prompt, Claude matches it against those descriptions. Only the matching skill's full body gets pulled into context.

Why "conditional" makes sense: the SKILL.md sits on disk the whole time. The headers (name + description) are scanned once and stay in context as tiny breadcrumbs. The body is read from disk only when a match happens, then dropped from context when the session ends. Anthropic calls this progressive disclosure.

What an actual SKILL.md looks like

SKILL.md --- name: git-commit-writer description: Writes conventional commit messages from staged git diffs. Use when the user asks for a commit message, wants to summarize staged changes, or asks "what should I commit this as". allowed-tools: Bash Read --- # Git Commit Writer ## Workflow 1. Run `git diff --staged` to see what's staged. 2. If nothing is staged, ask the user to stage their changes. 3. Pick a conventional commit type (feat, fix, chore, docs, refactor). 4. Write a subject line under 50 characters. 5. Add a body if the change is non-trivial.

MCP is plumbing, not a file.

MCP is not a file. It is not a folder. It is not a description in markdown. It is a running program that exposes tools over a documented protocol, plus a tiny JSON config that tells Claude how to launch or reach that program.

USB-C is the right analogy: build one server for Postgres and it works with Claude, ChatGPT, Cursor, anything that speaks MCP. OpenAI adopted MCP in March 2025. Google DeepMind in April. Anthropic donated it to the Linux Foundation at the end of 2025.

exposestools, resources, prompts

The three pieces in motion

Step 01
Host
Claude Desktop, Claude Code, Cursor, etc. The thing you actually talk to. It runs an MCP client inside.
→
Step 02
Protocol
JSON-RPC messages flow over stdio (local) or HTTP (remote). Client asks "what tools?", server lists them. Client calls a tool, server runs it.
→
Step 03
Server
A separate program. The one that actually talks to GitHub, Postgres, your filesystem, an API.

The actual config file on Windows 11

Edit %APPDATA%\Claude\claude_desktop_config.json, paste in your snippet, save, fully quit and restart Claude Desktop. The server appears as a hammer icon.

claude_desktop_config.json { "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\Users\\you\\Documents"] }, "github": { "command": "docker", "args": ["run", "-i", "--rm", "ghcr.io/github/github-mcp-server"], "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxx..." } } } }
Skills are static instructions. MCP is a live network connection to running code. That is the deepest difference between them.

A Plugin is the shipping container.

If a Skill is a recipe card and an MCP server is the kitchen plumbing, a Plugin is the whole kitchen, fully stocked and ready to cook. A Plugin is a folder that bundles Skills, MCP server configs, slash commands, hooks, and subagents into one installable package.

Plugins shipped with Claude Cowork on January 30, 2026. As of May 16, 2026 there are 1,163 plugins across 69 marketplaces. Anthropic just released 12 legal practice-area plugins plus 20+ new connectors on May 13, 2026.

The one-line mental model: Skills teach Claude how. MCP gives Claude access. Plugins ship both.
