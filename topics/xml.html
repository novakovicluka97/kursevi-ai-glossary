XML (in AI Prompting)

In AI context, XML tags are paired delimiters like <instructions>...</instructions> used to structure prompts with clear, unambiguous boundaries that the model can reliably identify and follow.

Why XML Tags for AI Prompts?

Claude has been specifically fine-tuned to pay attention to XML tag structure in prompts. Anthropic's official guidance: "Mark up your prompts with XML tags. Claude has been specifically tuned to pay special attention to your structure."

The technical reason: tokenization can cause problems when you rely on whitespace and indentation (the model might not "see" the spaces the same way you do). XML tags provide multi-line certainty — they are clear delimiters that unambiguously mark where a section begins and ends, regardless of how the tokenizer splits the text.

When to Use XML Tags

  • Production prompts with strict structure requirements
  • Multi-section prompts where the model must distinguish between instructions, context, examples, and user input
  • Extraction tasks where you need the model to isolate a specific section from a long input
  • System prompts for applications built on the Claude API

Practical Examples

<system>
You are a customer support agent for Acme Corp.
Only answer questions about our products.
</system>

<context>
{{retrieved product documentation from RAG}}
</context>

<user_message>
{{the customer's actual question}}
</user_message>

<instructions>
Answer the customer's question using only the context provided.
If the answer isn't in the context, say "I'll escalate this to a human agent."
</instructions>

XML vs. Markdown in Prompts

XML tags are the stronger structural signal for Claude. Use them to separate sections.
Markdown is better for formatting content within sections (headings, lists, bold text).

Best practice: use XML to define the architecture of your prompt, and Markdown for the readable content inside. They complement each other.

Note: As models become more capable, the exact formatting matters less. But for production systems where reliability is critical, XML structure still gives the most consistent results.

Common Tag Conventions

  • <instructions> — What the model should do
  • <context> — Background information or retrieved documents
  • <examples> — Few-shot examples
  • <input> — The actual data to process
  • <output_format> — How to structure the response
  • <constraints> — Rules or limitations

Layman's Analogy

XML tags are like labeled folders on a desk. If you give someone a stack of loose papers, they have to guess what's what. But if you put instructions in a folder labeled "INSTRUCTIONS," context in a folder labeled "CONTEXT," and the question in a folder labeled "QUESTION" — they know exactly where to look for each piece. XML tags are those folder labels for AI.
