Workflow

A workflow is a predetermined sequence of steps where you define the path and the LLM executes each step — but never decides what to do next. This contrasts with AI agents, where the model dynamically chooses its own path.

What is a Workflow?

A workflow is any repeatable process with defined steps. In traditional business: "receive order → process payment → ship product → send confirmation email." In AI: "receive user request → search knowledge base → generate draft → check for accuracy → deliver response."

The critical insight: in a workflow, the code defines what happens at each step. The LLM does the work, but never makes strategic decisions about what to do next. The path is hardcoded in your script.

Workflow vs Agent: The Key Distinction

Workflow Agent
Who decides the next step? You (the developer) The model
Predictability High — same path every time Variable — depends on what model finds
Cost Predictable, usually lower Variable, can spiral
Flexibility Rigid — change the path, change the code Handles edge cases you didn't plan for
Best for Repetitive, well-defined tasks Open-ended, novel tasks

Anthropic's strong advice: start with a single prompt, then a workflow, and only reach for an agent when the task genuinely needs the LLM to make decisions about what to do next. Most production "AI agents" are actually workflows — and that is correct.

Anthropic's Workflow Building Blocks

Anthropic identifies five composable patterns for building AI workflows, from simplest to most complex:

1. Prompt Chaining

The simplest pattern: a fixed sequence of LLM calls where the output of one becomes the input to the next. Each step has its own specialized prompt. Like a relay race — each runner (prompt) handles their leg, then passes the baton.

2. Routing

One LLM call classifies the input, then directs it to the appropriate specialized path. After that one decision, the path is fixed. See the full Routing topic for details.

3. Parallelization

Fan-out: send the same input to multiple LLMs simultaneously (e.g., generate 3 different drafts). Fan-in: aggregate the results (e.g., pick the best one, or combine insights from all three). Trades cost for speed and quality.

4. Orchestrator-Workers

One LLM breaks a task into subtasks and delegates them — but the workers execute fixed, predetermined operations. The orchestrator adds a light layer of dynamic task decomposition while keeping execution predictable.

5. Evaluator-Optimizer

A generate-then-evaluate loop: one LLM produces output, another evaluates it against criteria, and the first revises based on feedback. The iteration pattern is predetermined (generate → evaluate → revise), even though the content evolves.

Layman's Analogy

A workflow is like an assembly line in a factory. Each station does one specific job, and the product moves from station to station until it's complete. The assembly line never decides to skip a station or add a new one — that's predetermined by the factory manager. AI workflows are the same: the "stations" are AI operations, and the "product" is information being processed and refined at each step.

Real-World Example: E-Commerce Review Pipeline

An online shop gets 50 customer reviews daily in mixed languages and wants a summary report:

Step 1: Take each review → LLM prompt: "Translate this to English." → Output: English review.

Step 2: Take English review → LLM prompt: "Classify as positive, neutral, or negative." → Output: a label.

Step 3: Send all 50 classified reviews → LLM prompt: "Write a one-paragraph summary highlighting the top three complaints and top three praises." → Output: daily report.

Each step is hardcoded. The code says "first translate, then classify, then summarize." The LLM never decides what to do next — it just executes the task in front of it. This is a workflow, not an agent.
