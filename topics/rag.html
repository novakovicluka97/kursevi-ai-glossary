RAG (Retrieval-Augmented Generation)

RAG is a technique that improves LLM responses by first retrieving relevant information from external sources, then providing that information to the model as context before it generates an answer.

What is RAG?

Large language models have two fundamental limitations: their knowledge has a cutoff date (they don't know about recent events), and they can hallucinate (confidently state incorrect information). RAG solves both problems by giving the model access to up-to-date, authoritative sources at query time.

The process: (1) User asks a question → (2) System searches a knowledge base for relevant documents → (3) Retrieved documents are added to the prompt → (4) LLM generates an answer grounded in those sources.

How RAG Works

  1. Indexing: Documents are split into chunks and converted to embeddings (numerical representations), stored in a vector database
  2. Retrieval: When a query comes in, it's also converted to an embedding, and the system finds the most similar document chunks
  3. Generation: The retrieved chunks are passed to the LLM along with the question, and it generates an answer based on that specific information

Why Use RAG?

  • Answers are grounded in real sources (less hallucination)
  • Knowledge stays current without retraining the model
  • Much cheaper than fine-tuning a model on your data
  • You can cite sources for transparency

Layman's Analogy

RAG is like an open-book exam versus a closed-book exam. Without RAG, the AI answers purely from memory (which might be wrong or outdated). With RAG, the AI first looks up the relevant textbook pages, then answers using those sources — much more accurate and verifiable.
