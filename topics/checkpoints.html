Checkpoints & Rewind

A checkpoint is an automatic snapshot of a Claude Code session — its messages, file changes, and context — that you can rewind to, letting you undo work or explore a different approach safely.

What are Checkpoints?

Every time you submit a prompt, Claude Code quietly saves a checkpoint. If a change goes wrong or you simply want to try something else, you can return to any earlier checkpoint instead of manually unpicking the work. Checkpoints persist across sessions and are kept for 30 days by default.

Rewinding

Press Esc twice, or use the /rewind slash command, to open the checkpoint browser. Picking a checkpoint offers five choices:

OptionEffect
Restore code and conversationRevert both files and messages to that point
Restore conversationRewind messages only; keep current code
Restore codeRevert file changes only; keep the conversation
Summarize from hereCompress the conversation forward to free context space
Never mindCancel and stay where you are

Checkpoints vs. Git

Checkpoints are not a replacement for version control. They are instant and capture the conversation as well as files, but they are session-based and don't track changes made outside Claude Code (or by shell commands like rm and mv). The healthy pattern: use checkpoints for rapid experimentation, and commit finished work to git for a permanent, auditable history.

Layman's Analogy

Checkpoints are like the quick-save feature in a video game. Before a tricky section you save, attempt it, and if it goes badly you reload and try a different tactic — no progress permanently lost. Git, by contrast, is like writing your achievements into the official record book: slower, deliberate, and permanent.
