Routing

Routing is an AI workflow pattern where one classification decision directs the input to the appropriate specialized path — like an air traffic controller sending each plane to the right runway based on a quick assessment.

What is Routing?

A router evaluates an incoming request and dispatches it to the right handler. After that one decision, the path is fixed and predetermined. This makes routing a workflow pattern, not an agent pattern — the system makes one decision, then follows a defined track.

This is one of Anthropic's five core building blocks for agentic systems, sitting between simple prompt chaining (zero decisions) and full agents (many decisions).

Why Routing Matters (2026)

  • Cost savings: Research by LMSYS (RouteLLM) shows intelligent routing can reduce costs by over 85% — sending simple queries to smaller, cheaper models
  • Quality: Specialized prompts and models per category outperform one-size-fits-all
  • Speed: Lightweight models handle easy tasks in milliseconds
  • Scale: 37% of enterprises now use 5+ models in production — routing is how they manage this complexity

Routing Approaches

  • Keyword/rule-based: Cheapest and fastest. "If message contains 'billing', route to billing handler." Least flexible.
  • LLM-as-classifier: One LLM call to categorize the input, then route to the appropriate specialized path. Most common pattern.
  • Local classifier models: Fine-tuned lightweight models (BERT-class) that detect task type — coding, math, analysis, creative writing, etc. Fast and cheap at inference.
  • Confidence-based: If the model's confidence falls below a threshold, escalate to a larger/better model. Used for cost optimization.
  • Consensus-based (2026): Send the same prompt to multiple models and aggregate their responses — emerging pattern for high-stakes decisions.

Routing vs Agent Decision-Making

A router makes one decision at the start. An agent makes many decisions throughout execution.

If your problem needs exactly one classification step followed by specialized handling, use routing. If it needs ongoing judgment calls where each step depends on the previous result, use an agent.

Layman's Analogy

Routing is like calling a company's phone line. The automated menu asks "Press 1 for billing, 2 for tech support, 3 for sales." One decision routes you to the right department, and from there the process is fixed. The menu didn't have a conversation with you — it just classified your need and sent you on your way.

Real-World Example: Customer Support

A customer support system receives a message. A router classifies it: billing / technical / sales / complaint. Each category routes to its own specialized prompt, model size, and response template. Technical queries go to a large model with code tools and documentation access. Simple billing questions ("what's my balance?") go to a smaller, cheaper model with database access. One decision, then a fixed path.
