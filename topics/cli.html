Claude Code CLI

The CLI (Command-Line Interface) is how you launch and control Claude Code from your terminal — the claude command, its flags, and its modes for interactive use and scripted automation.

Interactive Mode vs. Print Mode

Running claude with no arguments starts an interactive REPL — a back-and-forth session with conversation history, tab completion, and slash commands. Adding the -p (print) flag switches to headless mode: Claude answers a single query and exits, with no interface. Print mode is what makes Claude scriptable.

CommandWhat it does
claudeStart an interactive session
claude -p "query"Answer one query, then exit (headless)
claude -cContinue the most recent conversation
cat log.txt | claude -p "explain"Pipe content in for analysis

Headless Mode for Automation

Because print mode reads from standard input and can emit JSON (--output-format json), Claude Code drops into pipelines and CI/CD jobs like any other command-line tool. A GitHub Actions workflow can run claude -p to review every pull request automatically — the same way it might run a linter or test suite.

Permission Modes

The --permission-mode flag controls how much autonomy Claude Code has, balancing speed against oversight:

ModeBehavior
defaultAsk for approval on risky actions
planRead-only — analyze and plan, change nothing
acceptEditsAuto-accept file edits, ask for the rest
autoApprove safe actions, prompt on risky ones

Flags like --model (choose Opus, Sonnet, or Haiku), --allowedTools, and --max-turns give finer control still — useful when you want a fast, cheap, tightly-scoped run.

Layman's Analogy

Interactive mode is like having a conversation with a colleague at your desk. Print mode is like leaving them a sticky note with one task — you come back later and the answer is done. The same person, two ways of working: one for thinking together, one for handing off a job to run on its own.
