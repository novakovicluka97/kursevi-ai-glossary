Markdown Format

Markdown is a lightweight text formatting language that uses simple symbols (like # for headings, * for bold) to structure documents. It's the preferred format for communicating with AI models because it survives preprocessing, is human-readable, and carries structural meaning that models have deeply learned.

What is Markdown?

Markdown was created in 2004 by John Gruber as a way to write formatted text using plain characters. Instead of clicking buttons to make text bold (like in Word), you wrap it in asterisks: **bold**. Instead of using a menu to create a heading, you prefix with hashes: # Heading.

It's used everywhere in tech: GitHub READMEs, Reddit posts, Stack Overflow answers, documentation sites, blog platforms, chat platforms (Slack, Discord), and even Wikipedia (which uses a wiki markup that converts cleanly to Markdown). All of these are prominent in AI training data.

Why Markdown Works So Well for AI

LLMs are not trained on raw HTML the way many people assume. Training data from web crawls (like Common Crawl) goes through heavy preprocessing: HTML tags get stripped, text gets extracted, the document is cleaned. The model rarely sees raw <h1> or <div> tags.

This is exactly why Markdown is so powerful for AI: it survives preprocessing because it IS plain text with a few special characters. When the training pipeline strips HTML from a GitHub README, the Markdown formatting remains intact. The model has seen billions of examples of Markdown structure and learned what it means:

  • # is a top-level header: The model treats text under bigger headers as more structurally important
  • **bold** and *italic* carry semantic weight: The model learns these are emphasis markers signaling importance
  • Lists signal discrete items: The model treats bulleted content as separate, parallel points
  • Code blocks signal literal content: The model knows not to paraphrase text inside backticks

When to Use Markdown (vs. Other Formats)

The practical rule for working with Claude:

  • Markdown for documents, RAG context, agent instructions (CLAUDE.md files, skills), READMEs — anything humans will also read
  • XML tags for production prompts with strict structure, multi-section prompts, or when the model must extract a specific section from a long input
  • JSON when you need structured output or are feeding structured data

Note: Anthropic states that the exact formatting is becoming less important as models become more capable. But for reliability in production, structure still helps.

Basic Markdown Syntax

# Heading 1
## Heading 2

**bold text**
*italic text*

- Bullet point
- Another point

1. Numbered list
2. Second item

[Link text](https://example.com)

`inline code`

```
code block
```

Example: Structured Prompt vs. Plain Text

Plain text (worse): "I want you to analyze this code for bugs and also suggest improvements and format the output nicely"

Markdown (better):

## Task
Analyze the following code.

## Requirements
1. Identify any bugs
2. Suggest improvements
3. Rate overall quality (1-10)

## Output Format
Use headings for each section.
