Plugins

A plugin is a bundled, installable package that combines multiple Claude Code features — slash commands, subagents, MCP servers, and hooks — into one cohesive extension installed with a single command.

What is a Plugin?

Plugins are the highest-level way to extend Claude Code. Rather than copying a slash command here, configuring a subagent there, and wiring up hooks separately, a plugin packages all of it together. A user runs /plugin install pr-review and instantly gets every command, agent, and hook the plugin author bundled — fully configured.

How a Plugin Is Built

At its core a plugin is a folder with a .claude-plugin/plugin.json manifest declaring its name, version, and author. Around that manifest sit optional directories: commands/, agents/, skills/, hooks/, and MCP configuration. Claude Code reads the manifest, extracts the components, and registers them.

The Marketplace

Plugins are distributed through marketplaces — catalogs of available plugins. There is an official Anthropic-managed marketplace, community marketplaces, and private ones that companies run internally for their own tools and standards. Marketplaces can be added from a GitHub repository, a git URL, or a local path.

When to Use a Plugin

A single slash command or skill is fine for a personal, one-off workflow. Reach for a plugin when you need to bundle several features, share a setup with a team, or publish for distribution. Onboarding a new teammate becomes one install command instead of an afternoon of manual configuration.

Layman's Analogy

If a slash command is a single app, a plugin is an app bundle — and the marketplace is the app store. Instead of hunting down and configuring five separate tools, you install one package and everything works together out of the box, just like buying a productivity suite instead of assembling it piece by piece.
