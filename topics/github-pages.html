GitHub Pages (Deploying a Static Site)

GitHub Pages is a free hosting service by GitHub that turns a repository of HTML files into a live website with a real URL — the standard way to host static sites like documentation, portfolios, and glossaries.

What is GitHub Pages?

GitHub is where developers store and collaborate on code. GitHub Pages is a feature that takes a repository (a project folder on GitHub) and serves its HTML files as a public website. No server setup, no hosting fees, no configuration. You push your files, GitHub hosts them.

Your site gets a URL like https://yourusername.github.io/your-project/. You can also connect a custom domain (like yourbrand.com) later.

Prerequisites

You need two tools installed on your computer:

  • Git — Version control (tracks changes to your files). Check: git --version
  • GitHub CLI (gh) — GitHub's command-line tool. Check: gh --version

If you don't have them:

# Install Git (if not already installed)
# Download from https://git-scm.com/downloads

# Install GitHub CLI
winget install GitHub.cli      # Windows
brew install gh                # macOS

# Authenticate (one-time setup)
gh auth login

Step-by-Step: Deploy Your Site

Step 1: Initialize Git

Open your terminal, navigate to your project folder, and initialize a Git repository:

cd /path/to/your-project
git init

What this does: Creates a hidden .git folder that tracks all changes to your files. Your project is now a Git repository.

Step 2: Stage and Commit Your Files

git add .
git commit -m "Initial commit: project files"

What this does: git add . tells Git to track all files in the folder. git commit saves a snapshot of your project with a description message. Think of it as pressing "Save" with a label.

Step 3: Create the GitHub Repository and Push

gh repo create your-project-name --public --source=. --push

What this does: This single command does three things at once:

  1. Creates a new repository on your GitHub account
  2. Connects your local folder to that repository
  3. Pushes (uploads) all your files to GitHub

Use --public for a site anyone can view, or --private if you want to restrict access (GitHub Pages still works with private repos on paid plans).

Step 4: Enable GitHub Pages

gh api repos/{owner}/{repo}/pages -X POST \
  -f source.branch=main \
  -f source.path=/

Replace {owner} with your GitHub username and {repo} with the repository name.

What this does: Tells GitHub to serve your main branch as a website, using the root folder (/) as the source.

Alternative: You can also do this in the browser — go to your repository on github.com → Settings → Pages → select "main" branch → Save.

Step 5: Visit Your Live Site

Wait about 60 seconds, then visit:

https://yourusername.github.io/your-project-name/

Your site is now live on the internet with HTTPS, accessible to anyone.

Updating Your Site

After making changes to your files locally, push updates with:

git add .
git commit -m "Description of what you changed"
git push

GitHub Pages automatically rebuilds your site within seconds of each push. No redeployment needed.

Optional: Custom Domain

To use your own domain (e.g., glossary.yourbrand.com):

  1. Buy a domain from any registrar (Namecheap, Cloudflare, Google Domains)
  2. Add a CNAME record pointing to yourusername.github.io
  3. In your repo, go to Settings → Pages → Custom domain → enter your domain
  4. GitHub provides free HTTPS for custom domains automatically

Your Live URL

Once deployed, your site is immediately accessible at: 

https://yourusername.github.io/your-repo-name/

This is the fastest way to see your deployment — no dashboard needed. Just construct the URL from your GitHub username and repository name. For example, user janedoe with repo my-portfolio would visit https://janedoe.github.io/my-portfolio/.

GitHub Pages vs Netlify

Both are popular free options for hosting static sites. Here's how they compare:

GitHub PagesNetlify
CostAlways free (public repos)Free tier, 100GB bandwidth/month limit
Setupgit push — that's itConnect repo or drag-and-drop
What it hostsStatic files only (HTML/CSS/JS)Static files + serverless functions
Build toolsJekyll only (or pre-built files)Many (React, Vue, Hugo, Next.js, etc.)
FormsNot includedBuilt-in form handling
Custom domains1 per siteMultiple per site
Default URLusername.github.io/repoproject.netlify.app

Verdict: For plain HTML/CSS/JS sites, GitHub Pages is the simpler choice — zero configuration, no bandwidth limits that matter, and you already use Git for version control. Netlify is better when you need build pipelines for frameworks, serverless functions, or built-in form handling. Neither URL is SEO-friendly by default; use a custom domain for that.

What GitHub Pages cannot host: Server-side applications (Node/Express, Django, Rails), anything requiring a database, or apps needing server-side processing at request time. It serves static files only.

Why GitHub Pages?

  • Free: No hosting costs for static sites
  • Professional: Real URL with HTTPS, not file:///C:/...
  • Version controlled: Every change is tracked in Git history
  • Auto-deploys: Push code → site updates automatically
  • Reliable: Backed by GitHub's infrastructure (99.9% uptime)
  • Industry standard: Used by millions of developers and companies

Layman's Analogy

Dragging an HTML file into your browser is like printing a flyer and showing it to someone by hand. Deploying to GitHub Pages is like putting that flyer on a billboard on a public street — anyone with the address can see it, it's always there, and you can update it anytime by pushing a button from your desk.

Complete Example: From Zero to Live

# Navigate to your project
cd /c/PROJECTS/kursevi-ai-glossary

# Initialize Git and make first commit
git init
git add .
git commit -m "Initial commit: AI Glossary with 36 topics and quiz"

# Create repo on GitHub and push (one command)
gh repo create kursevi-ai-glossary --public --source=. --push

# Enable GitHub Pages
gh api repos/YOUR_USERNAME/kursevi-ai-glossary/pages \
  -X POST -f source.branch=main -f source.path=/

# Wait ~60 seconds, then visit:
# https://YOUR_USERNAME.github.io/kursevi-ai-glossary/
